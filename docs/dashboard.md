# Dashboard Guide

The dashboard is a React + Vite app for inspecting the project outputs without
opening raw JSON files by hand. It combines aggregate arbitration summaries,
embedded D3 pages, and BPMN process diagrams.

## Run locally

From the repository root:

```bash
# Rebuild the overview payload if needed.
uv run python scripts/process_arbitration_for_dashboard.py

# Start the web app.
cd dashboard
npm install
npm run dev
```

For a production build:

```bash
cd dashboard
npm install
npm run lint
npm run build
```

## Data inputs

| Input | Used by | Notes |
| --- | --- | --- |
| `dashboard/public/data/dashboard_data.json` | Arbitration Overview tab | Generated by `scripts/process_arbitration_for_dashboard.py` from cleaned arbitration data |
| `dashboard/public/bpmn/` | Process Diagrams tab | Static BPMN XML assets loaded by `bpmn-js` |
| `dashboard/public/d3/*.html` | D3 Visuals tab | Static D3 pages embedded in iframes |
| `data/processed/d3/*.json` | D3 pages | Per-case D3 payloads generated by `scripts/export_d3_all.py` |
| `data/processed/d3/manifest.json` | Audit/export status | Records which cases exported successfully and which did not |

## Tabs

### Arbitration Overview

Loads `/data/dashboard_data.json` and renders:

- headline case metrics
- statement-count distribution
- user/admin party links
- common remedy verbs
- average duration gauge

This tab is useful for quick project demos, but it depends on the cleaned
arbitration aggregate used by `scripts/process_arbitration_for_dashboard.py`.
For final coverage counts, prefer `docs/handoff.md`.

### D3 Visuals

Embeds four static D3 pages:

- `case_browser.html` - per-case editor timeline and dispute explorer
- `arbitration_timeline.html` - arbitration case activity spans
- `recurring_editor_disputes.html` - editors appearing in multiple cases
- `recurring_arbitration_timeline.html` - recurring dispute/topic timelines

These pages use the per-case payloads in `data/processed/d3/`.

### Process Diagrams

Loads static BPMN XML files from `dashboard/public/bpmn/` and renders them with
`bpmn-js`. The screen includes examples for:

- arbitration cases
- RfC cases
- DRN cases
- aggregate workflows

The displayed BPMN files are curated examples, not a complete inventory of all
481 ArbCom cases.

## What "466 D3 payloads" means

At handoff, `data/processed/d3/` contains 466 JSON files. That count includes
`manifest.json`; the manifest currently reports 465 successful per-case exports
and 16 skipped/no-data cases for that export run. This processed layer should
be regenerated after repairing the nine zero-data raw records so raw usable
coverage and D3/dashboard coverage agree.

Regenerate with:

```bash
uv run python scripts/export_d3_all.py --workers 4 --force
```

Then inspect `data/processed/d3/manifest.json` for `cases_with_data`,
`cases_no_data`, and per-case errors.

## Troubleshooting

- If the overview tab fails to load, check that
  `dashboard/public/data/dashboard_data.json` exists.
- If D3 pages load but show missing cases, inspect
  `data/processed/d3/manifest.json`.
- If BPMN diagrams fail to render, confirm the referenced files exist under
  `dashboard/public/bpmn/`.
- If raw or processed JSON files look like tiny pointer files, run
  `git lfs pull`.
